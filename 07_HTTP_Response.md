# HTTP Response

## Purpose

This document describes the HTTP responses generated during the ERP Vendor Payment Integration process.

The response communicates the result of the Payment Acquisition request submitted to the Finance Portal.

After the payment approval process is completed, the approved document is retrieved through a separate HTTP `GET` request and made available to the Vendor Portal.

---

## Response Flow

The response process consists of two stages:

```text
Vendor Portal
      |
      | POST Payment Acquisition Request
      ▼
Integration Layer
      |
      | Forward Request
      ▼
Finance Portal
      |
      | Payment Approval Process
      |
      ▼
Approval Result
      |
      | HTTP Response
      ▼
Integration Layer
      |
      | Process Response
      |
      | GET Approval Document
      ▼
Approved Payment Document
      |
      ▼
Vendor Portal
```

The Integration Layer processes the response from the Finance Portal and determines the next step based on the returned status.

---

## 1. Payment Acquisition Response

### HTTP Status

A successful Payment Acquisition request returns an HTTP success status.

| HTTP Status | Meaning | Integration Handling |
|---|---|---|
| `200 OK` | Request processed successfully | Process the response |
| `400 Bad Request` | Request contains invalid data | Reject request and record error |
| `401 Unauthorized` | Authentication failed | Record authentication error |
| `403 Forbidden` | Request is not permitted | Record authorization error |
| `404 Not Found` | Requested resource or endpoint not found | Record integration error |
| `500 Internal Server Error` | Finance Portal encountered a system error | Record system error |

The exact HTTP status codes supported by the production API depend on the implementation of the Finance Portal.

---

## Response Headers

A successful JSON response contains the following headers:

| Header | Purpose |
|---|---|
| `Content-Type` | Defines the response body format |
| `Accept` | Defines the expected response format |

Example:

```http
Content-Type: application/json
```

---

## Response Body

The Payment Acquisition response communicates the processing result and, when applicable, provides the identifier required to retrieve the approved document.

### Example Successful Response

```json
{
  "status": "APPROVED",
  "approval_document_id": "1",
  "vendor_id": "1"
}
```

The `approval_document_id` identifies the approval document generated by the Finance Portal.

The identifier is subsequently used together with the `vendor_id` to retrieve the approved document.

---

## Response Data

| Response Field | Data Type | Required | Description |
|---|---|---|---|
| `status` | String | Yes | Result of the payment approval process |
| `approval_document_id` | String | Yes when approved | Identifier of the generated approval document |
| `vendor_id` | String | Yes | Vendor associated with the payment request |

### Supported Approval Status

```text
APPROVED
REJECTED
```

When the status is `APPROVED`, the Integration Layer proceeds with the approval document retrieval process.

When the status is `REJECTED`, no approval document is retrieved and the rejection is handled according to the applicable business process.

---


## 2. Approval Document Retrieval

After receiving an approved response, the Integration Layer retrieves the signed payment approval document using a separate HTTP `GET` request.

### Request

```http
GET /invoice?approval_document_id=1&vendor_id=1
```

The request uses the `approval_document_id` returned by the Payment Acquisition response together with the associated `vendor_id`.

---

## Document Response

The document retrieval request returns the approved payment document.

Example:

```http
HTTP/1.1 200 OK
Content-Type: application/pdf
```

The response contains the digitally signed PDF document.

The Integration Layer validates the returned document before storing or making it available through the Vendor Portal.

---

## Integration Logging

The Integration Layer records the outcome of integration operations in the `Integration Log`.

The logging mechanism is independent from the business entities and is used to provide a technical record of integration execution.

### Example: Payment Request

| log_id | log_status | log_date | log_time | operation | source_system | target_system |
|---:|---|---|---|---|---|---|
| 100001 | SUCCESS | 2026-08-09 | 10:15:22 | SUBMIT_PAYMENT_REQUEST | VENDOR_PORTAL | FINANCE_PORTAL |

### Example: Approval Response

| log_id | log_status | log_date | log_time | operation | source_system | target_system |
|---:|---|---|---|---|---|---|
| 100002 | SUCCESS | 2026-08-09 | 10:15:25 | APPROVAL_RESPONSE | FINANCE_PORTAL | INTEGRATION_LAYER |

### Example: Document Retrieval

| log_id | log_status | log_date | log_time | operation | source_system | target_system |
|---:|---|---|---|---|---|---|
| 100003 | SUCCESS | 2026-08-09 | 10:15:28 | RETRIEVE_APPROVAL_DOCUMENT | INTEGRATION_LAYER | FINANCE_PORTAL |

The log records:

- Integration status
- Date and time
- Operation performed
- Source system
- Target system

No foreign-key relationship to the business tables is required because the Integration Log is intended to independently record technical integration activity.

---

## Error Logging

When the HTTP response or approval document fails validation, the Integration Layer records the failure in the Error Log.

Example:

| log_id | error_type | reason | error_log_time |
|---:|---|---|---|
| 500001 | INVALID_RESPONSE | Approval document ID is missing | 2026-08-09 10:16:02 |
| 500002 | DOCUMENT_VALIDATION | Returned document is not a valid PDF | 2026-08-09 10:17:14 |
| 500003 | HTTP_ERROR | Finance Portal returned HTTP 500 | 2026-08-09 10:18:31 |

Detailed error classification and handling procedures are documented in `09_Error_Handling.md`.

---

## End-to-End Response Processing

The complete response process can be summarized as:

```text
Finance Portal
      |
      | Payment Approval Response
      ▼
Integration Layer
      |
      ├── Validate HTTP Status
      |
      ├── Validate Approval Status
      |
      ├── Retrieve approval_document_id
      |
      ├── Record Integration Log
      |
      └── GET Approval Document
                |
                ▼
        Validate Signed PDF
                |
                ▼
        Store / Make Available
                |
                ▼
          Vendor Portal
```
